# 右侧实时决策卡片

卡片位于画面右侧上部，默认宽 200 px，右距 16 px、顶部 140 px，深色半透明背景。它独立于原生画布，不缩小中央道路或车辆。仅「详情」按钮接受鼠标点击，卡片主体允许鼠标穿透，不播放循环闪烁或重复入场动画。

## 模型与参数

```text
StartLux 27B                  详情 ↓
681ms · 置信93% · 思考关
指令  左翻滚并喷气
车辆  右翻滚中 · 喷气保持
```

以上为展示格式示例，不是实测数据。

- **模型**来自响应的实际 `model` 字符串。StartLux 型号突出品牌，并在名称含 `27b` 等规模信息时解析显示；其他模型如实显示名称，缺失显示待确认。悬停模型区域可看完整名称。
- **ms**是该条模型请求的客户端往返耗时，包含网络与服务端处理；不代表纯模型推理耗时或当前车辆动作持续时间。
- **置信度**来自接口的 `confidence` / `probability`。它不等于动作成功率、安全概率或已经执行的证明。
- **思考状态**来自响应 `details.thought.used`；缺失时显示未知。客户端配置和后端实际遥测分别处理，不用配置值伪装实际状态。

当前有效指令显示它自己的参数。指令过期后收为约 32 px 的单行提示：保留模型、明确标为「上次」的响应耗时与「决策中／等待决策」，不继续挂旧动作。紧凑模式隐藏规模、置信度、思考参数和车辆行，完整内容仍在下方详情中。

窗口宽度不超过 640 px 或高度不超过 500 px 时，有效指令也使用单行布局，右距缩为 8 px。极短窗口进一步上移卡片。

## 指令和车辆分别显示

**指令**只展示最新一条已接受的模型选择。其提示时限为 `appliedAtMs + durationMs`，由回执声明的动作窗口决定：普通动作默认为 200 ms，翻滚约 533 ms。到期由本地单次计时器立即清除，即使下一条响应尚未到达。

该时限只规定**提示有效期**，不能据此声称车辆还在执行动作。车辆行独立读取原生状态，包括实际翻滚方向、排队翻滚、换道以及喷气／俯冲／加速保持。因此「指令左翻滚、车辆右翻滚中」可能同时成立；已提交翻滚也可能因能量不足或原生时机而未启动。

新指令替换旧指令，不堆积历史；相同动作连续提交只更新内容。过期、被拒绝、跨局或终局后返回的响应不会成为当前指令。停止接管、原生终局或原生暂停时隐藏卡片；重新开始会建立新会话，旧指令不能复活。

## 消息新鲜度

独立的 `ROADSTER_LIVE` 消息包含会话标识及开始时间、局标识 `epoch`、顺序号、采样时间、驾驶阶段、当前接受的指令、模型响应参数和最小原生车辆状态。

- 后台每 100 ms 非重叠采样，不调用模型，不重新计算 11 项预测，不修改输入、游戏时钟或驾驶看门狗。
- 拒绝乱序消息、旧会话、已退役局和终局后的旧消息。
- 原生采样超过 300 ms 不再显示活动状态；实时消息整体超过 300 ms 则隐藏卡片。
- 仅更新变化的文字，按最近到期时间安排单次清除计时器，不在每个渲染帧重建 DOM。

100 ms 是计划采样周期，不是后台浏览器的准时保证；新鲜度判断也在页面端独立执行。

## 详情与导出

点击「详情」才滚动到游戏页面下方，不自动展开历史或自动滚屏。按钮阻止驾驶按键事件继续传播；滚动与查看历史不调用暂停、输入或时钟接口。原游戏自身的失焦暂停仍适用，见[时钟边界](architecture.md#时钟与暂停)。

下方面板离开视口时暂缓记录 DOM 更新，保留最新数据；进入视口后再渲染，右侧卡片在查看下方面板期间隐藏。默认只列出已提交指令，可勾选查看未提交响应。导出保留当前缓冲区内的完整回执，含未执行原因，最多 200 条决策；它不是无限历史，也不含 Key。

单元测试覆盖指令到期但无新响应、旧局及乱序消息、停止与重开、真实翻滚方向、排队与能量不足、原生状态失效、下方面板懒更新和导出边界。真实网络延迟、设备帧率和游戏升级后的行为仍需在目标浏览器验证。
